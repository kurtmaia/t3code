# Side conversations

Long answers bury follow-up questions. Instead of asking "what about that part?" at the bottom of
the thread, open a side conversation on the exact passage you mean.

## Starting one

On web and desktop, select any text in an assistant message and click **Ask about this**. A panel
opens beside the thread with your quote at the top; type your question and send. Nothing is created
until that first send, so closing the panel costs nothing.

On mobile, long-press an assistant message and choose **Ask about this** — the whole message is
quoted, and your question starts the side conversation from there.

## What a side conversation is

It is a real thread, linked to the passage it was opened from. It shares the parent thread's
workspace, so the agent can read the same code your question is about, and it starts in the
parent thread's mode: plan mode if the parent is planning, otherwise the normal mode. The mode
toggle in the panel switches between them; in the normal mode the agent may edit files, and it
works in the same workspace as its parent.

The quoted passage stays highlighted in the parent thread, with a chip under the message for each
side conversation opened from it. Click either to reopen the panel. Deleting a side conversation
removes its highlight and chip.

In the sidebar, side conversations sit indented under their parent thread. If the parent is ever
deleted, they move to the top level rather than disappearing.

## When to use it

A side conversation is for questions scoped to one point: "why this trade-off?", "what does this
term mean here?", "would that break X?". Because it starts fresh with just the quote, answers stay
focused on the passage instead of the whole history. For anything bigger — new work, multi-step
changes — **Open as full thread** in the panel header promotes it to a normal thread view with the
full composer.
